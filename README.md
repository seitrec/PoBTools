# PoB Tools

Data extraction + local HTML visualizations for Path of Building (PoE1, PoB Community).

## Use

```
npm install          # once
npm run view         # parse all builds, write out/index.html and open it
npm run build        # same without opening
node serve.mjs       # optional: serve out/ on http://localhost:8765
```

`out/index.html` is self-contained (data embedded) and opens straight from disk.
`out/data.json` holds the same data for other scripts.

Paths live in `config.json` (builds folder, PoB install dir).

## What gets extracted (`lib/parse-build.mjs`)

Per build: class/ascendancy/level/bandit/pantheon, every saved `PlayerStat`/`MinionStat`, skill sets → socket
groups → gems (level, quality, colour + tags from PoB's `Data/Gems.lua`), item sets → slot → parsed item
(rarity, base, props, implicits/explicits with the selected variant and rolled ranges resolved, crafted/fractured
flags), tree specs (allocated nodes, mastery picks, jewel sockets, bloodline), notes. PoB loadout tags (`{n}` at
the end of set titles) are parsed into `loadout`.

Tree geometry (`lib/tree.mjs`) is read from PoB's local `TreeData/<ver>/tree.lua`, using PoB's orbit-angle maths.
Cluster-jewel nodes (ids ≥ 65536) are generated by PoB at runtime and are not in the static tree data.

Stats are whatever PoB last saved into the XML: they are only as fresh as the last time the build was opened and
saved in PoB.

## pob-mcp

`pob-mcp/` is a clone of https://github.com/ianderse/pob-mcp, registered in `.mcp.json` for Claude Code sessions
opened in this folder. It's in XML-only mode for now. Turning on the calc engine (`POB_LUA_ENABLED=true`) needs a
LuaJIT interpreter (`POB_CMD`); that's the next step for "what-if" data (node/gem DPS impact).
